## 2024-05-24 - DoS and Masked Auth Bypass via `secrets.compare_digest` with NoneType
**Vulnerability:** Instances of `secrets.compare_digest(a, b)` across the codebase lacked explicit validation that `a` and `b` were not `None`.
**Learning:** Python's `secrets.compare_digest` raises a `TypeError` if either argument is `NoneType`. An attacker could exploit this by providing inputs that evaluate to `None` in the backend, leading to unhandled exceptions (DoS) or masking subtle authentication bypass logic depending on the `except Exception` handling or caller path. Also, when negating this compound check, the `not` vs `and` operator precedence makes `not a is not None and ...` evaluate as `(not a is not None) and ...` which is completely incorrect.
**Prevention:** Always wrap negated explicit token validation in parentheses: `not (a is not None and b is not None and secrets.compare_digest(a, b))`. Never pass unvalidated (potentially `None`) inputs to cryptographic or constant-time comparison functions.
