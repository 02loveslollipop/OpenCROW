## 2025-07-27 - [CRITICAL] Timing Attack Vulnerability in System Token Validation
**Vulnerability:** System token validation used the `in` operator to check if a token is valid (`token in self.settings.system_tokens`), which uses a non-constant time string equality check. This allows for a timing attack where an attacker can determine the system token character by character.
**Learning:** Python's string equality and `in` operators are optimized to return early on a character mismatch. When comparing cryptographic secrets or tokens, this leaks timing information based on how many characters matched before the difference.
**Prevention:** Always use `secrets.compare_digest()` for comparing secrets, tokens, passwords, and API keys. To check membership in a list of secrets, iterate and use `secrets.compare_digest()` on each item instead of the `in` operator. Before doing so, ensure the input token is validated (e.g. `if not token: return False`) to prevent TypeErrors with None values.
