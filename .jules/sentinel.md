## 2025-02-24 - Fix Unhandled PyMongo Exceptions in GridFS Download
**Vulnerability:** The `download_file` and `download_challenge_file` methods in `services/constellation/constellation/storage.py` directly called `grid_out = self.bucket.open_download_stream(ObjectId(file_id))`. If the file_id was an invalid ObjectId, it raised `bson.errors.InvalidId`. If the file did not exist, it raised `gridfs.errors.NoFile`. These exceptions were unhandled, bubbling up to the Tornado handlers which would log an error and raise a 500 status code, potentially leaking internal state.
**Learning:** Storage layer methods interacting with external systems (like MongoDB) should translate internal database exceptions to domain-appropriate exceptions (like `KeyError`) to allow higher layers (like web handlers) to gracefully handle them (e.g., returning 404 Not Found).
**Prevention:** Catch external database library exceptions like `bson.errors.InvalidId` and `gridfs.errors.NoFile` in the storage layer and translate them to domain exceptions (like `KeyError`).

## 2025-02-24 - Fix Unhandled TypeErrors in Token Comparisons
**Vulnerability:** The project uses `secrets.compare_digest` to verify tokens and secrets, which is good practice to avoid timing attacks. However, in several places (e.g. `packages/mcp/core/opencrow_worker_runner.py`, `services/constellation/constellation/storage.py`, `services/constellation/constellation/backend.py`), the inputs to `secrets.compare_digest` were not explicitly checked to be not `None`. `secrets.compare_digest` raises a `TypeError` if it receives a `None` argument, which can lead to Denial of Service or masked authentication bypasses if unhandled in specific contexts.
**Learning:** Even when using secure standard library functions, the types of the inputs must be validated to prevent unhandled exceptions that can impact application stability or security.
**Prevention:** Always validate that both inputs to `secrets.compare_digest` are not `None` before comparing them.
