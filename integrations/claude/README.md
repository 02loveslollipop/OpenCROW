# Claude Code integration

OpenCROW uses Claude Code Agent Skills, a user-scope MCP server, and native `SessionStart`, `PreToolUse`, `PostToolUse`, `PreCompact`, and `Stop` command hooks. Hook failures are visible but fail open; lifecycle blockers use exit status 2.

Hooks are merged into `~/.claude/settings.json` (`settings.fragment.json`). The lifecycle MCP server is **not** placed there: Claude Code ignores `mcpServers` in `settings.json` and reads user-scope servers from `~/.claude.json`. The installer registers `mcp.fragment.json` with `claude mcp add-json --scope user` when the CLI is on `PATH`, so the write goes through Claude Code's own config handling, and falls back to an atomic merge of `~/.claude.json` when the CLI is absent or exits successfully without persisting the entry (wrappers, test shims). It refuses to touch an unparseable `~/.claude.json`, because the CLI would replace it with a fresh file. Older installs that wrote the server into `settings.json` are migrated on install, update, or `opencrow integrations repair`; `opencrow doctor` reports the integration unhealthy when the server is not registered.

Constellation consumes stream-JSON, saves Claude's native session ID, and resumes with `--resume` on trusted full-auto runtime hosts. OpenCROW records native-install ownership around the [official Claude Code installation](https://code.claude.com/docs/en/setup) and limits explicit CLI purge to receipt-owned `.local/bin` and `.local/share/claude` assets; `.claude` configuration and history are never removed.
